# ✅ Исправлено: База данных теперь внутри бота (SQLite)

## Что было не так?
На хостингах типа Koyeb Free, Render Free, Amvera без `persistenceMount` — файлы в папке `data/` стираются после перезапуска/редеплоя. Поэтому все заявки, пользователи, тикеты пропадали.

## Что сделано?

### 1. Встроенная БД SQLite (`bot.db`)
Теперь **все данные хранятся в одном файле** `data/bot.db` (стандартная библиотека Python `sqlite3`, без внешних зависимостей).

Внутри две таблицы:
- `kv_store(name, data)` — здесь лежат все бывшие JSON: `users.json`, `states.json`, `applications.json`, `tickets.json`, `appeals.json`, `roles.json`, `moderation.json`, `settings.json`
- `counters(kind, value)` — атомарные счетчики для ID

**Плюс двойная запись:** каждая запись пишется и в SQLite, и в старый JSON файл как бэкап. Если что — можно восстановить.

### 2. Автомиграция
При первом запуске бот сам:
- создает `data/bot.db`
- если в `data/` есть старые `*.json` — импортирует их в SQLite
- делает бэкап в `data/backups/`

### 3. Автобэкапы
Каждые 60 минут и при старте бот делает:
- копию `bot.db` -> `data/backups/bot_YYYYMMDD_HHMMSS.db`
- JSON дамп всех данных -> `data/backups/dump_*.json`
- хранит последние 20 копий, старые удаляет

### 4. Постоянные тома на хостингах

**Amvera (у тебя уже было правильно):**
```yaml
persistenceMount: /data
```
Файл уже настроен в `amvera.yaml` — просто заливаешь код, данные будут жить в `/data/bot.db`

**Render:**
Обновлен `render.yaml` — добавлен диск:
```yaml
disks:
  - name: zrg-data
    mountPath: /data
    sizeGB: 1
env:
  DATA_DIR: /data
```
На Render нужно в настройках сервиса включить Disk (доступно от платного тарифа 1GB $0.1/мес, или можно без диска — но тогда данные будут теряться).

**Koyeb:**
Обновлен `koyeb.yaml` — добавлен пример volume. На бесплатном тарифе Koyeb дисков нет!
Варианты:
- Купить Koyeb Volume (платно)
- Деплоить на Amvera (там бесплатно постоянный диск)
- Использовать Render с диском
- Или хотя бы делать /export в ТГ вручную из админ-панели

### 5. Экспорт улучшен
Команда в админ-панели **📦 Экспорт JSON** теперь выдает ZIP с:
- все JSON файлы
- `bot.db` — полная база
- `backups/` — последние бэкапы
- `full_dump_*.json` — весь дамп из SQLite в одном файле

### 6. Что делать чтобы не терялось на ЛЮБОМ хостинге?

**Вариант A — правильный (рекомендую):**
1. Деплой на Amvera с `persistenceMount: /data` — там бесплатно и файл сохраняется навсегда
2. Или на Render с диском

**Вариант B — если хостинг без диска:**
1. Регулярно жми в боте Админ-панель -> 📦 Экспорт JSON — качай бэкап
2. Если потерялось — просто закинь `bot.db` обратно в `data/` через файловый менеджер хостинга и перезапусти

**Вариант C — будущее:**
Можно добавить автобэкап в Telegram канал или Google Drive, если хочешь — скажи, допишу.

## Как обновить существующий бот?

1. Скачай новый `bot.py` из этой папки
2. Замени старый `bot.py` на сервере / на GitHub
3. Оставь папку `data/` как есть (если она уже есть) — бот сам смигрирует JSON в `bot.db`
4. Перезапусти бот
5. Проверь лог: должно быть `SQLite DB ready: /data/bot.db (WAL mode)` и `DB INIT: ...`
6. В админ-панели нажми 📦 Экспорт — убедись что внутри есть `bot.db`

## Проверка что работает

Логи при старте:
```
SQLite DB ready: /data/bot.db (WAL mode)
DB INIT: /data/bot.db exists=True DATA_DIR=/data
ONLINE @your_bot
POLL READY
```

Команды:
- `/id` — проверит что бот жив
- Админ-панель -> 📦 Экспорт JSON — должен содержать bot.db

Файлы:
- `data/bot.db` — основная база
- `data/bot.db-wal`, `data/bot.db-shm` — временные файлы SQLite WAL (это нормально)
- `data/backups/` — бэкапы
